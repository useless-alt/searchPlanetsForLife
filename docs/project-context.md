# Глобальный контекст проекта (Shared Context)

Источник: блок «Часть 1. Глобальный контекст проекта», приложенный к промптам-задачам (14.11.2026).
Документ обязателен для всех задач серии (Задачи 1–31) и не подлежит переписыванию без явного решения владельца проекта.

---

## 1.1. Назначение

Веб-приложение. Загружает каталог экзопланет из 6 JSON-API, дедуплицирует его и восстанавливает пропуски каскадным решателем (Уровни А/Б/В). Считает индексы обитаемости в 4 режимах, строит Топ-50, показывает таблицу, 3D-карту Галактики и 3D-сцену системы. Весь UI на русском.

## 1.2. Стек

В ТЗ стек не задан («код сайта появится позже», п. 11.8.5). Принят следующий, см. U18:

| Слой | Решение |
|---|---|
| Язык | TypeScript 5.x, `strict: true`, `noUncheckedIndexedAccess: true` |
| Менеджер | npm workspaces, Node.js ≥ 20 |
| `packages/shared` | чистый TS без DOM/Node API: типы, константы, физика, индексы, ранжирование |
| `apps/server` | Node.js + Fastify: адаптеры источников, резервные копии, дедупликация, REST |
| `apps/web` | Vite + React 18 + Three.js + Zustand; тяжёлый пересчёт в Web Worker |
| Тесты | Vitest (во всех пакетах) |
| Линт/формат | ESLint + Prettier |

Причина разделения: запросы к TAP-эндпоинтам из браузера блокируются CORS, а часть эндпоинтов (`http://…`) недоступна со страницы по HTTPS. Резервные копии лежат в файловой системе сервера (`data/backups/<source>/`, п. 8.1). Пересчёт полного массива при смене режима и параметров выполняется на клиенте, «мгновенно» (п. 3).

## 1.4. Сквозные соглашения

- Единицы внутри кода: R, M в земных; L, `st_rad`, `st_mass` в солнечных; d (большая полуось) в а.е.; P в сутках; S в земных потоках; температуры в К; расстояние до системы `dist_pc` в парсеках.
- Отсутствие значения = `null`. Подстановка случайных или «правдоподобных» значений запрещена (п. 1, Уровень В).
- Функции в `shared` чистые: без мутации входа, без NaN/Infinity в выходе. Невычислимое значение возвращается как `null`.
- Provenance (происхождение значения): `measured` (зелёный) / `physics` (синий) / `model` (жёлтый) / `estimate` («Оценка», п. 11.1, цвет не задан, U15).
- Происхождение значения, вычисленного из других значений: берётся худшее из происхождений входов в порядке `measured < physics < model < estimate`. Если все входы `measured` или `physics`, результат — `physics` (решение исполнителя, в ТЗ не описано).
- Правило приоритета документа: при конфликте раздел 11 > разделов 4, 9, 10 (п. 11, шапка). Раздел 13 описывает элементы референса; при конфликте с 11.2 побеждает 11.2 (U12).
- Все пользовательские строки хранятся в `apps/web/src/i18n/ru.ts`. Строки из ТЗ копируются дословно.
- Аутентификации, ролей и БД в ТЗ нет. Миграций нет, хранилище только JSON-файлы. П. 8.5 (Supabase) помечен «в текущий объём работ не входит», в план не включён.
- **Уточнение по п. 8.5 (задача 11a, 15.11.2026).** Supabase используется не как БД приложения, а как внешнее хранилище резервных копий каталога: приватный бакет Storage и две таблицы (`catalog_snapshots`, `catalog_rows`) с RLS без политик. Рабочее хранилище приложения остаётся прежним — JSON-файлы в `apps/server/data/backups/` (п. 8.1), сайт читает данные через `GET /api/catalog` и к Supabase не обращается. Ключ (`sb_secret_…` / `service_role`) живёт только в `.env.local` на машине и в секретах CI; в браузерный бандл не попадает. Обновление — по расписанию, новая выгрузка заменяет прежнюю только после успешной загрузки (см. `docs/supabase-refresh.md`).
- **Правило визуального слоя.** Перед написанием UI-кода (задачи 12a–29) агент читает SKILL.md скилла `@design-taste-frontend`. Скилл определяет **только визуальный стиль**: типографику, цвета, отступы, компоненты. Тексты, поведение и состав элементов берутся из ТЗ. Раздел 11.2 («чистый экран, лишнее скрыто по умолчанию») главнее любых декоративных решений скилла.
- **Целевые устройства — только ПК и ноутбуки** (решение владельца проекта, 14.11.2026). Минимальная ширина окна 1024 px, рабочая — 1280 px и выше. Мобильные раскладки, «одна колонка», мобильные меню и подписи под пикселем не проектируются; ниже 1024 px страница прокручивается по горизонтали (уточнение U66). Проверки скилла на 390/320/768 не применяются, требования к касанию (44 px) остаются как ориентир для мыши и трекпада.
