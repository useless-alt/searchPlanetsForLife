# Параллельная работа и слияние

Правила для нескольких агентов, работающих над задачами 27a–31 одновременно.
Обязательны вместе с [`AGENTS.md`](../AGENTS.md), п. 7.

Основание: задачи 27a–31 затрагивают одни и те же файлы UI (`store.ts`, `ru.ts`,
`App.tsx`, `tokens.css`), поэтому без фиксированных фаз, границ потоков и
порядка слияния конфликты неизбежны.

---

## 1. Фазы

| Фаза | Задачи в работе | Порядок слияния | Гейт перед слиянием |
|---|---|---|---|
| 0 | `27a-data` | `27a-data` | `npm run typecheck`, `npm test` |
| 1 | `27a-theme` ‖ `28-backend` ‖ `31-server` | `27a-theme` → `28-backend` → `31-server` (области не пересекаются) | `npm run typecheck`, `npm test` |
| 2 | `27b` | `27b` | `npm run typecheck`, `npm test` |
| 3 | `27c` | `27c` | `npm run typecheck`, `npm test` |
| 4 | `29` ‖ `28-UI` ‖ `27d` | `29` → `28-UI` → `27d` | `npm run typecheck`, `npm test`; после слияния `27d` — ещё `npm run test:layout` |
| 5 | `28-bridge` | `28-bridge` | `npm run typecheck`, `npm test`, `npm run test:layout` |
| 6 | `30` | `30` | `npm run typecheck`, `npm test`, `npm run test:layout` |
| 7 | `31-specs` | `31-specs` | `npm run typecheck`, `npm test`, `npm run test:layout` |

Порядок в фазе 4 обязателен: `27d` проверяет итог всех трёх веток, поэтому
сливается последним.

Ветки с суффиксами (`27a-data`, `27a-theme`, `28-backend`, `28-UI`, `28-bridge`,
`31-server`, `31-specs`) — это части задач 27a, 28 и 31; что именно входит в
каждую часть, задают постановки этих задач. Здесь фиксируются только порядок
слияния и границы.

`npm run test:layout` создаётся в `27d`. До слияния `27d` этой команды в
репозитории нет, и её отсутствие не считается ошибкой гейта.

---

## 2. Ветки и рабочие копии

- Каждой задаче — своя ветка и свой `git worktree` вне корня репозитория:
  ветка `<id>` (`27a-data`, `28-UI`, `29`), каталог `../exo-wt/<id>`.
- В каждом worktree — свой `npm install`: `node_modules` не общий.
- Один агент — один worktree. Файлы чужого worktree не редактируются.
- Слияние выполняет тот, кто ведёт фазу; он же отвечает за гейт после слияния.

---

## 3. Гейт после слияния

После каждого слияния, в слитой ветке:

1. `npm run typecheck` — без ошибок;
2. `npm test` — все тесты;
3. с момента слияния `27d` — дополнительно `npm run test:layout`.

Красный гейт означает, что слияние не завершено: следующие фазы не начинаются.

`27c` не добавляет отдельного скрипта: unit-тесты раскладки входят в `npm test`.
`27d` создаёт `npm run test:layout` — Playwright-аудит наложений: правила `R1–R10`,
состояния `S00–S19`, размеры от 1440×900 до 320×640. Состав правил и состояний
задаётся постановкой `27d`.

**Про ширины меньше 1024 px.** По U66 минимальная рабочая ширина — 1024 px,
ниже страница прокручивается по горизонтали. Аудит на 320–1023 px проверяет, что
внутри прокручиваемого полотна нет наложений, а не что прокрутки нет.

---

## 4. Общие файлы: правило блоков

Файлы, где конфликты вероятны:

- `apps/web/src/state/store.ts`
- `apps/web/src/i18n/ru.ts`
- `apps/web/src/i18n/help.ru.ts`
- `apps/web/src/App.tsx`
- `apps/web/src/styles/tokens.css`
- `package.json`
- `apps/web/src/extra/registry.ts`

Правило:

- каждая задача добавляет свои строки **в конец отдельного блока** с
  комментарием `// --- <id> ---` (в CSS — `/* --- <id> --- */`);
- существующие строки не переставляются, не переформатируются и не
  «причёсываются»;
- порядок блоков — по возрастанию фазы, затем по ID;
- в `package.json` комментариев нет, поэтому новые скрипты и зависимости
  добавляются в конец соответствующего объекта, существующие ключи не
  переупорядочиваются;
- удаление чужого блока или слияние блоков в один — запрещено.

## 5. Границы потоков

| Поток | Задача | Не трогает |
|---|---|---|
| B | `28-UI` | `apps/web/src/three/**`, `SystemController.ts` — это `28-bridge` (фаза 5) |
| C | `29` | `apps/web/src/components/**`, кроме `SceneControls.tsx` |

Нарушение границы — не «мелкая правка», а перенос работы в фазу 5.

---

## 6. Конфликтные точки

- `SceneControls.tsx` — надписи из `29` и атрибуты аудита из `27d`. Обе задачи
  правят один файл, поэтому `27d` сливается после `29`; блоки не смешиваются.
- `ru.ts` — строки `29` и `27d`; тот же порядок блоков.
- `App.tsx`, `tokens.css`, `extra/registry.ts` — только добавление блоков.

---

## 7. Если `test:layout` сломался

После слияния `27d` красный `test:layout` исправляет **тот, кто сливал
последним**. Он же перезапускает гейт и, если нужно, откатывает своё слияние.
Переносить исправление на автора задачи нельзя: автор уже не владеет
итоговым состоянием ветки.
