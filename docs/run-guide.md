# Как запустить проект у себя

Инструкция для проверяющего: от чистого клона до работающего сайта за три
команды. Проект не требует ключей, аккаунтов и внешних сервисов.

## Требования

- **Node.js ≥ 20** (`node -v`);
- npm (идёт вместе с Node);
- ~500 МБ на `node_modules` и сборку;
- Windows, macOS или Linux.

## Запуск

```bash
git clone https://github.com/useless-alt/searchPlanetsForLife.git
cd searchPlanetsForLife
npm ci
npm start
```

Открыть **http://localhost:8787**.

`npm start` собирает веб-приложение и поднимает сервер, который отдаёт и
статику, и REST API с одного порта.

### Что должно быть на экране

- каталог из **18 455 планет** — он читается из снимка
  `data/demo/catalog.json.gz`, который лежит в репозитории;
- 3D-карта и список работают сразу, **сеть для старта не нужна**;
- в шапке — счётчики и статус источников.

Если видно пустой экран и «нет ни одной планеты» — сервер не нашёл стартовый
снимок; смотрите лог запуска, строка `[start] стартовый снимок: …`.

## Обновление реальных данных

Данные тянутся из шести источников (NASA, Exoplanet.eu, Exo-MerCat, Gaia,
SIMBAD, Exo.MAST). Два способа:

| Способ | Что делает |
|---|---|
| кнопка «Обновить» в интерфейсе | пересобирает каталог в памяти сервера, API отдаёт старый снимок до готовности нового |
| `npm run refresh` | то же плюс записывает слитый снимок в `data/backups/merged/latest.json` |

Первое обновление идёт **1–2 минуты** (шесть источников, пагинация).
Если `EXO_AUTO_REFRESH=1`, обновление стартует сразу после запуска сервера.

## Резервные копии

Копии пишутся **автоматически при каждом успешном ответе API** — ничего
настраивать не нужно.

```
data/backups/<источник>/latest.json            # актуальная копия
data/backups/<источник>/<ГГГГММДД_ЧЧММСС>.json # версия, хранится 5 последних
data/backups/merged/latest.json                # слитый каталог (только npm run refresh)
```

- Путь считается **от корня репозитория**, даже если команда запущена из
  `apps/server` (это важно: `npm start -w @exo/server` работает именно там).
- Если запрос к источнику не прошёл, сервер берёт данные из `latest.json`,
  помечает записи как `fromBackup` и показывает бейдж «резерв».
- В репозитории уже лежат `latest.json` всех шести источников — это страховка
  на случай, если у проверяющего API недоступны.
- Слитый снимок обновляется **только** командой `npm run refresh`, кнопка в
  интерфейсе его не пишет.

Порядок выбора стартового снимка: `EXO_SNAPSHOT` → `data/backups/merged/latest.json`
→ `data/demo/catalog.json.gz`.

## Полезные переменные

Скопируйте `.env.example` в `.env` (все значения опциональны):

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `8787` | порт HTTP-сервера |
| `BACKUP_DIR` | `data/backups` | каталог копий (от корня репозитория) |
| `EXO_AUTO_REFRESH` | пусто | `1` — обновлять сразу после старта |
| `EXO_SNAPSHOT` | — | свой файл снимка (JSON или `.json.gz`) |
| `FETCH_TIMEOUT_MS` | `30000` | таймаут запроса к API |

## Если что-то не работает

- **`npm.ps1 не может быть загружен` (Windows/PowerShell)** — политика
  запуска скриптов. Запускайте через `cmd /c "npm start"` либо один раз
  выполните `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
- **Порт занят** — `PORT=8788 npm start` (Linux/macOS) или
  `cmd /c "set PORT=8788 && npm start"` (Windows).
- **Долго висит «загрузка»** — источники недоступны; подождите таймаут
  (30 с на запрос) или задайте `EXO_AUTO_REFRESH=0` и работайте на снимке.
- **Раздел реконструкции пуст** — это ленивый Exo.MAST: он запрашивается при
  открытии карточки планеты и без сети недоступен.
