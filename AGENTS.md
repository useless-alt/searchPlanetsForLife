# AGENTS.md — постоянные инструкции по репозиторию exo-habitability

## 1. Протокол чтения (главное правило)

1. У каждой задачи есть манифест входных файлов. Читай **только** их.
2. **Не запускай рекурсивный листинг корня репозитория.** Он вытягивает
   ~850 служебных файлов, которые не имеют отношения к задаче:
   801 файл в `.agents/skills/**/assets`, 46 в `data/backups`, файлы
   `archive/supabase`. Для понимания кода они не нужны.
3. Игнорируй при обходе: `data/`, `archive/`, `supabase/`, `node_modules/`,
   `.agents/skills/**/assets`.
4. Не читай `apps/web/src` и `apps/server/src` без прямой необходимости.
5. Нужен файл вне манифеста → сначала `grep` с узкими `path`/`include`.
   Листинг репозитория заменяй на `git show --stat <commit предыдущей задачи>`:
   это точный перечень файлов зависимости. Например, `git show --stat 2317c80`
   даёт весь состав Задачи 5 — то есть поверхность зависимостей Задачи 6.
6. Сомневаешься, нужен ли файл, — не читай, спроси.

## 2. Скиллы — отдельный механизм, не часть протокола чтения

- Скиллы **не подгружаются чтением папки**. OpenCode объявляет их
  автоматически (ID, имя, описание), а тело — по вызову инструмента `skill`
  с точным ID. В этом репозитории скилл один:
  `design-taste-frontend` (`.agents/skills/design-taste-frontend/SKILL.md`).
- Пункт 3 выше относится **только к обходу репозитория**. Файлы скилла
  (`references/`, `library/`, `assets/`) читай, когда сам скилл это требует:
  OpenCode их не подгружает автоматически.
- **Перед написанием UI-кода (задачи 12a–29) обязательно загрузи скилл
  `design-taste-frontend`** — требование проекта
  (`docs/project-context.md`, п. 1.4 «Правило визуального слоя»).
  Скилл задаёт только визуальный стиль: тексты и поведение берутся из ТЗ.

## 4. Соглашения

- **Целевые устройства — только ПК и ноутбуки.** Мобильными устройствами
  (телефоны, планшеты) не занимаемся: цель проекта — десктопное
  приложение. Минимальная ширина окна 1024 px, рабочая — 1280 px и выше.
  Следствия: не проектируются мобильные раскладки, «одна колонка»,
  полноэкранное меню и подписи под пикселем; проверки скилла
  `design-taste-frontend` на 390/320/768 не применяются; ниже 1024 px
  страница прокручивается по горизонтали. Требование «касаемая цель не
  меньше 44 px» остаётся в силе. Решение владельца проекта, зафиксировано
  также в `docs/project-context.md`, п. 1.4.
- Комментарии и doc-комментарии — по-русски, со ссылками на пункты ТЗ
  (например, «п. 10.5», «U20»).
- Prettier: `printWidth: 100`, `singleQuote`, `trailingComma: all`, `semi`.
- TypeScript: `strict` + `noUncheckedIndexedAccess` — индекс массива даёт
  `T | undefined`, проверяй или используй `??`.
- ESLint: `@typescript-eslint/consistent-type-imports` — типы импортируются
  через `import type`.
- Тесты: Vitest. Фикстуры собираются вручную из `ResolvedPlanet`
  (`makeParam` / `nullParam`), чтобы параметры задавались точно.
- Имена функций-компонентов и тестов — по-русски.

## 6. Делегирование субагентам

Субагенты бесплатные, поэтому экономят не деньги, а контекст основного
агента: их внутренние чтения и логи не попадают в мой контекст. Но запуск
тоже стоит — ребёнок заново читает инструкции, а его отчёт всё равно
возвращается ко мне. Делегируй только когда выигрыш больше этой цены.

| Субагент | Когда использовать |
|---|---|
| `scout` | найти файл или символ, прочитать фрагмент, ответить «где лежит» |
| `runner` | прогнать тесты, `tsc`, ESLint или Prettier и получить только ошибки |
| `scribe` | переименования, опечатки, форматирование, доки по готовому образцу |

- Хорошо делегируется: объёмный вывод проверок (`npm test`, `tsc`, ESLint по
  всему репо), широкий поиск по многим файлам, массовые однотипные правки.
- Не делегируй мелочь: прочитать один файл, поправить 1–2 строки, точечный
  `grep` — быстрее и дешевле сделать самому.

- `scout` и `runner` ничего не редактируют, `scribe` не запускает команды.
- В задаче указывай точные пути, ожидаемый результат и границу
  («не трогай X», «только эти файлы»).
- Архитектуру, выбор решения и финальную проверку оставляй основному агенту.
- Если субагент ответил `НУЖНО РЕШЕНИЕ`, реши вопрос сам и запусти его снова
  с уточнённой формулировкой.
- «Мышление» выбирай по задаче: у `beam-free` есть варианты `low`, `medium`,
  `high`, `xhigh`, `max`. По умолчанию `runner` и `scribe` идут на `low`;
  для неочевидных правок или сложного вывода запускай с
  `model: opencode-go/beam-free#high` (или `#max`). У `longcat` и `iceman`
  вариантов нет — для задачи с мышлением используй `beam-free`.
